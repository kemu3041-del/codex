# `particle/base` 粒子模型项目知识点

## 1. 项目定位

这是一个把 GLB 模型转换成发光粒子，并提供“聚拢入场 → 鼠标排斥 → 滚动/点击散场”交互的 Vite + React Three Fiber Demo。

适用场景：品牌 Logo 首屏、活动开场、产品轮廓展示、页面转场。当前工程化版本需要 Vite 构建，不能直接把 JSX 复制到只支持 HTML/CSS/JS 的 SaaS 源码区。

## 2. 技术栈与文件职责

| 文件/依赖 | 职责 |
| --- | --- |
| `index.html` | 挂载节点、模型地址配置、加载/入场/散场回调、ENTER 按钮 |
| `src/main.jsx` | 创建 React 根节点并加载全局样式 |
| `src/App.jsx` | 当前使用版本：模型采样、粒子数据、Shader、逐帧交互、外部通信 |
| `src/App第一版.jsx` | 通过粒子 Raycaster 获取排斥点，带呼吸 Shader |
| `src/App第二版.jsx` | 改为“射线与虚拟平面求交”，避免拾取大量粒子 |
| `src/App第三版.jsx` | 增加鼠标活跃度衰减和非线性排斥力 |
| `public/*.glb` | 浏览器直接访问的模型资源 |
| `src/assets/studio007.hdr` | HDR 环境资源；当前代码没有使用 |
| React Three Fiber | 用 React 组件描述 Three.js 场景，并用 `useFrame` 接入渲染循环 |
| Drei | 提供 `useGLTF`、`useProgress`、`OrbitControls` 等辅助能力 |
| Three.js | BufferGeometry、ShaderMaterial、Raycaster、Plane、向量数学等底层能力 |
| `MeshSurfaceSampler` | 按三角形面积在网格表面均匀采样 |

## 3. 当前版本的数据流

1. `index.html` 通过 `window.APP_CONFIG.DYNAMIC_MODEL_URL` 指定模型。
2. `App` 读取地址并把它传给 `InteractiveModelParticles`。
3. `useGLTF(url)` 异步加载 GLB，`Suspense` 在资源就绪后挂载粒子组件。
4. `useMemo` 只在模型场景变化时生成粒子静态数据。
5. `<bufferGeometry>` 把位置、颜色、尺寸、透明度传给 GPU。
6. `useFrame` 每帧在 CPU 更新 position Buffer，实现聚拢、排斥和散场。
7. Shader 根据每个点的属性绘制圆形光点。
8. React 与宿主页通过 `window.startExit`、`window.onIntroFinish`、`window.onLoadProgress`、`window.onExitComplete` 通信。

## 4. GLB 模型粒子化

### 4.1 获取网格

代码用 `scene.traverse` 找到第一个 `isMesh` 节点。因此当前逻辑只粒子化模型中的第一个 Mesh，多 Mesh 模型需要合并几何体或逐个采样。

当前版会 clone Mesh 和 Geometry 后再缩放，避免直接修改 `useGLTF` 缓存中的共享模型。移动端比例为 `0.002`，桌面端为 `0.005`。

### 4.2 两种采样方式

- 表面采样：`MeshSurfaceSampler` 按三角面面积选点，适合实体填充。
- 边缘采样：`EdgesGeometry(geometry, 20)` 提取法线夹角超过阈值的边，再在线段两端之间随机插值。

当前版先把 75% 粒子分给边缘，25% 分给表面。在线段上取点的公式为：

```js
point = start + (end - start) * t; // t ∈ [0, 1)
```

边缘采样能强化 Logo 轮廓；表面采样避免内部完全空洞。`EdgesGeometry` 的阈值越小，提取的细节边越多，也越容易显得杂乱。

### 4.3 球面随机偏移

代码使用球坐标生成三维随机方向：

```js
theta = random * 2π;
phi = acos(2 * random - 1);
x = sin(phi) * cos(theta) * radius;
y = sin(phi) * sin(theta) * radius;
z = cos(phi) * radius;
```

使用 `acos(2r - 1)` 而不是直接随机 `phi`，是为了让方向在球面上均匀分布，避免粒子在两极聚集。

## 5. BufferGeometry 与类型化数组

每个粒子通过多个并行数组描述：

- `position`：当前可变位置，每粒子 3 个 `float`。
- `targetPositions`：模型聚拢后的理论位置。
- `color`：RGB，每粒子 3 个 `float`。
- `size`：点尺寸，每粒子 1 个 `float`。
- `opacity`：透明度，每粒子 1 个 `float`。
- `disperseDirections`：散场单位方向，每粒子 3 个 `float`。
- `types`：0 为核心粒子，1 为氛围粒子。
- `randomness`：计划用于粒子个体速度差异的随机数。

使用 `Float32Array` 的原因：连续内存、内存占用稳定，并且可直接上传为 WebGL BufferAttribute。修改 position 后必须设置：

```js
geometry.attributes.position.needsUpdate = true;
```

`startPositions.slice()` 很重要，它给可写的 position 创建副本，避免动画覆盖原始入场数据。

## 6. 自定义 Shader

### 6.1 顶点 Shader

顶点 Shader 读取 `size`、`opacity`、内置 `color`，先把粒子从模型空间转换到相机空间，再计算透视尺寸：

```glsl
vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
float atten = 300.0 / -mvPosition.z;
gl_PointSize = size * uPixelRatio * atten;
gl_Position = projectionMatrix * mvPosition;
```

离相机越远，`-mvPosition.z` 越大，点越小。乘 `uPixelRatio` 可减轻高 DPR 屏幕上的模糊，同时 Canvas 的 `dpr={[1, 2]}` 把最大像素比限制为 2，控制 GPU 压力。

### 6.2 片元 Shader

每个 `THREE.Points` 默认是方形点精灵。片元 Shader 用 `gl_PointCoord` 计算片元到中心的距离，丢弃圆外片元，再用 `smoothstep` 生成柔和光晕。

`transparent + depthWrite={false} + AdditiveBlending` 的组合适合发光粒子：亮部会叠加，且透明粒子不会把深度缓冲写死。但大量重叠会过曝，应同步控制粒子透明度、尺寸和密度。

当前 `uTime` 会逐帧更新，但当前 Shader 没有使用它；它可以删除，或用于呼吸、闪烁和噪声动画。

## 7. 三阶段动画

### 7.1 聚拢入场

粒子从随机的 `startPositions` 插值到 `targetPositions`：

```js
progress += delta * 0.5;
eased = 1 - Math.pow(1 - progress, 3); // easeOutCubic
position = lerp(start, target, eased);
```

使用 `delta` 而不是固定步长，可减少不同刷新率导致的动画速度差异。`easeOutCubic` 前快后慢，适合聚拢后稳定落位。

### 7.2 鼠标排斥与弹性复位

当前方案不对每个粒子做射线拾取，而是让相机射线与 `Z = 0` 的虚拟平面相交，直接得到鼠标的三维交互点。这比第一版 `raycaster.intersectObject(points)` 更稳定，复杂度也更低。

排斥力由四部分组成：

1. 粒子到鼠标交点的方向。
2. 半径范围判断。
3. 非线性距离衰减 `falloff`。
4. 鼠标活跃度与每粒子伪随机扰动。

粒子受力后再执行 `currentP.lerp(targetP_Base, 0.08)`，形成“推开后回弹”的粘滞感。这里的 `0.08` 是逐帧系数，不是严格的时间无关阻尼；若要求不同刷新率表现一致，可改为：

```js
const alpha = 1 - Math.exp(-returnSpeed * delta);
currentP.lerp(targetP_Base, alpha);
```

### 7.3 散场

散场可由三种入口触发：ENTER 按钮调用 `window.startExit()`、鼠标滚轮向下、移动端手指上滑超过 20px。

每个粒子的散场方向是“目标点背离模型中心的方向 + 随机扰动”，归一化后保存。核心粒子随散场时间加速，氛围粒子使用另一档速度；达到 `exitDuration` 后通知宿主页隐藏 Canvas。

## 8. React 与普通 HTML 的桥接

该项目使用 Window API 作为最小集成层：

| API | 调用方向 | 用途 |
| --- | --- | --- |
| `APP_CONFIG.DYNAMIC_MODEL_URL` | HTML → React | 注入模型 URL |
| `startExit()` | HTML → React | 启动散场 |
| `onLoadProgress(progress)` | React → HTML | 更新加载进度 |
| `onIntroFinish()` | React → HTML | 入场达到 80% 时展示 UI |
| `onExitComplete()` | React → HTML | 散场结束后切换主页面 |

这种方式适合把 React/WebGL 首屏嵌入旧站点。正式封装时应给事件加统一命名空间，并在卸载时清理暴露的方法和一次性状态，避免多次挂载相互污染。

## 9. 三个历史版本的演进

| 版本 | 核心变化 | 主要取舍 |
| --- | --- | --- |
| 第一版 | 25,000 粒子；对 Points 做 Raycaster；Shader 呼吸 | 视觉丰富，但拾取和 CPU 遍历成本高，循环内还有临时 Vector3 分配 |
| 第二版 | 20,000 粒子；射线与虚拟平面求交 | 交互定位更轻量，但排斥范围较小、状态较直接 |
| 第三版 | 10,000 粒子；鼠标活跃度衰减；高次幂 falloff | 空洞边缘更柔和，停止移动后自然恢复 |
| 当前版 | 2,000 粒子；边缘 + 表面混合采样；独立透明度；外部回调；散场 | 更偏实际首屏集成，但仍有若干数据和生命周期问题需要修正 |

## 10. 当前实现中值得修正的问题

1. `randomArr` 创建后没有赋随机值，所有元素都是 0。因此散场速度的“个体差异”实际没有生效，应在生成循环中执行 `randomArr[i] = Math.random()`。
2. `r > 0.3` 会让约 70% 粒子成为大范围氛围粒子，而不是少量溢出。它还会独立作用于边缘粒子，导致大量已采样的轮廓点被偏移 1.5～51.5 单位，可能削弱 75% 边缘采样的意义。
3. 注释描述的透明度范围与代码不一致；代码可能生成大于 1 的 alpha。建议把核心和氛围透明度限制在 `[0, 1]`。
4. `onExitComplete` 获取 `#main-content`，但当前 `index.html` 没有该节点，散场完成后访问 `content.style` 会抛错。
5. `window.hasCalledExit` 是全局一次性锁，重新挂载 App 时不会自动重置。
6. `useState(getInitialModelUrl)` 中的 setter 没有使用；若不支持运行时换模型，可直接保存常量。若需要换模型，应暴露明确方法并处理 GLTF 缓存和动画状态重置。
7. 当前只处理第一个 Mesh，也没有显式应用节点的世界变换。复杂 GLB 可能出现位置、旋转、缩放不正确。
8. 移动端/桌面端缩放只在粒子数据首次生成时判断，窗口跨过 768px 后不会重新采样。
9. `index.html` 引用了不存在的 `/vite.svg`，会产生 404；`studio007.hdr`、`WechatIMG718.jpg` 和 `src/assets/logo.glb` 当前未使用。
10. `three-stdlib` 被源码直接 import，但没有列为直接 dependency，只是由其他包间接安装。应显式添加依赖，避免上游依赖结构变化导致构建失败。
11. 每帧仍在创建 `Vector3`，并在 CPU 遍历全部粒子。2,000 粒子尚可；提高到数万时应复用向量，或把聚拢、排斥和散场迁移到 GPU Shader/GPGPU。
12. `useProgress()` 汇报的是 Drei 默认加载管理器中的全局进度；页面同时加载其他 Three.js 资源时，它不一定只代表当前 GLB。

## 11. 性能优化优先级

1. 先减少无效计算：仅在交互或动画阶段更新 position，静止时停止 CPU 遍历。
2. 循环外复用 Vector3，避免每帧垃圾回收。
3. 按设备能力配置粒子数、DPR、交互范围和散场复杂度。
4. 模型较复杂时预处理简化版 GLB，并压缩 Mesh/纹理资源。
5. 数万粒子时把位置计算移到顶点 Shader，CPU 只更新少量 uniform。
6. 页面退出时卸载 React Root 或 dispose Geometry、Material、监听器和缓存资源。
7. 为 `prefers-reduced-motion`、低性能设备和 WebGL 不可用场景提供静态 Logo 降级。

## 12. SaaS/CMS 接入建议

建议把以下内容作为平台字段或效果配置：

- 模型 URL。
- 粒子数量、边缘占比、边缘阈值。
- 主色、点尺寸、透明度。
- 核心/氛围粒子比例与散布半径。
- 入场时长、排斥半径、回弹速度。
- 散场触发方式、速度、时长。
- 入场完成和散场完成后的 DOM 行为。
- 移动端粒子数和静态降级图。

工程化 SaaS 可以保留 React 组件并用 props 或 adapter 注入配置。只支持粘贴代码的平台，需要先构建成单个 JS/CSS 产物，并确保 GLB 使用平台可公开访问的绝对地址或资源地址。

## 13. 推荐学习顺序

1. 理解 R3F 的 `Canvas`、`useFrame`、`useThree` 和 React Suspense。
2. 掌握 GLTF 场景树、Mesh、Geometry、局部/世界坐标。
3. 学习 BufferGeometry、BufferAttribute 和类型化数组。
4. 分别实践 `MeshSurfaceSampler` 与 `EdgesGeometry`。
5. 掌握球坐标随机分布、向量归一化、lerp 和缓动函数。
6. 理解 Raycaster 与数学平面求交。
7. 学习 Points 的顶点/片元 Shader、点精灵和混合模式。
8. 最后把 CPU 粒子动画迁移到 GPU，并补齐资源释放和移动端降级。

## 14. 本地验证

```bash
cd particle/base
npm install
npm run build
npm run dev
```

重点验证：GLB 是否加载、粒子是否在约 2 秒内聚拢、鼠标移动是否形成局部排斥、停止移动后是否回弹、ENTER/滚轮/触摸是否触发散场，以及散场结束后宿主页是否存在并正确显示 `#main-content`。
