# 轮廓粒子不显示问题复盘

## 问题现象

把 `desktopProfile.ambientCount` 调成 `0` 后，画面没有任何粒子。

这说明问题不只是“背景粒子遮住了轮廓”或“背景透明度太强”，而是轮廓粒子层本身没有正确渲染。

## 真实根因

根因是 **轮廓粒子层的 vertex attribute 设计超出了 WebGL 可用 attribute 数量限制，并且后续修复时出现了 shader 声明和 JSX 绑定不一致的问题**。

原始轮廓层使用了大量独立 attribute：

```text
position
aLocal
aStartCenter
aEndCenter
aColor
aStart
aDuration
aStartScale
aEndScale
aSize
aSeed
aArcX
aArcY
aDensity
aDepth
```

再加上 three.js / WebGL 管线可能保留或自动处理的 attribute，容易超过常见设备的 attribute 上限。典型浏览器报错会类似：

```text
VALIDATE_STATUS false: Too many attributes
```

一旦 shader validate 失败，整个轮廓 `points` 材质无法正常绘制，所以 `contourCount` 再大也看不到。

## 正确代码的关键修复

正确代码在 `src/App1.jsx` 中，核心做法是 **打包 attribute**。

把多个单独 float 合并成 `vec4` / `vec2`：

```glsl
attribute vec4 aTimeScale; // x: aStart, y: aDuration, z: aStartScale, w: aEndScale
attribute vec4 aVisual;    // x: aSize, y: aSeed, z: aArcX, w: aArcY
attribute vec2 aExtra;     // x: aDensity, y: aDepth
```

并且移除了重复的 `aLocal`，直接复用内置：

```glsl
vec3 transformed = center + position * scaleValue;
```

这样 attribute 数量明显下降，轮廓层可以正常通过 WebGL shader 校验。

## `App.jsx` 和 `App1.jsx` 的关键差异

`App1.jsx` 是一致的完整修复：

```jsx
<bufferAttribute attach="attributes-aTimeScale" args={[data.timeScale, 4]} />
<bufferAttribute attach="attributes-aVisual" args={[data.visual, 4]} />
<bufferAttribute attach="attributes-aExtra" args={[data.extra, 2]} />
```

`buildContourData()` 也对应返回：

```js
return {
  positions,
  startCenters,
  endCenters,
  colors,
  timeScale,
  visual,
  extra
};
```

而有问题的 `App.jsx` 出现了半改状态：

- shader 已经声明 `aTimeScale / aVisual / aExtra`
- JSX 仍然绑定旧的 `aStart / aDuration / aSize / aDepth...`
- `buildContourData()` 也仍然返回旧的分散数组

这会导致 shader 需要的 attribute 没有正确传入，轮廓层仍然无法可靠显示。

## 为什么一开始没有检查出来

主要有 4 个原因。

1. **只做了构建验证，没有完成浏览器 WebGL 运行时验证**

`npm run build` 只能证明 React/Vite 语法和打包通过，不能证明 WebGL shader 在浏览器中成功 validate。

WebGL 的 attribute 超限、shader validate failed、uniform/attribute 绑定错误，通常只会在浏览器运行时 console 里出现。

2. **调试方向先落到了透明度和出现时机**

当时现象是“看不到轮廓”，容易误判为：

- `revealProgress` 初始为 0
- `alpha` 被压低
- `contourTravelStrength` 把粒子推远
- 背景粒子遮住轮廓

这些确实会影响可见性，但不是根因。

3. **没有第一时间做层隔离测试**

正确的第一步应该是：

```js
ambientCount: 0
contourCount: 8600
```

如果只剩轮廓层仍然不可见，就应该立刻排查轮廓层 shader / attribute / geometry 绑定，而不是继续调透明度参数。

4. **没有加入强制可见 debug shader**

正确版 `App1.jsx` 加了 `uDebugMode`，可以强制：

```glsl
gl_PointSize = 16.0 * uPixelRatio;
vOpacity = 1.0;
gl_FragColor = vec4(1.0, 0.0, 1.0, 1.0);
```

这个开关可以快速判断：

- 点没有画出来：geometry / attribute / shader validate 问题
- 点画出来但正常模式不可见：透明度 / 尺寸 / 位置问题

之前没有这个开关，所以排查路径变慢。

## 后续排查清单

遇到 Three.js / shader 粒子层不可见时，按这个顺序检查：

1. **先隔离图层**

```js
ambientCount: 0
contourCount: 8600
```

确认轮廓层是否能单独显示。

2. **开启强制可见调试**

把轮廓材质里的：

```js
uDebugMode: { value: 1.0 }
```

如果粉色大点能显示，说明 shader 和 geometry 通了，再回头调透明度、大小、位置。

3. **检查 shader 声明和 JSX 绑定是否一一对应**

shader 中声明：

```glsl
attribute vec4 aTimeScale;
attribute vec4 aVisual;
attribute vec2 aExtra;
```

JSX 必须绑定：

```jsx
<bufferAttribute attach="attributes-aTimeScale" args={[data.timeScale, 4]} />
<bufferAttribute attach="attributes-aVisual" args={[data.visual, 4]} />
<bufferAttribute attach="attributes-aExtra" args={[data.extra, 2]} />
```

`buildContourData()` 必须返回对应数组。

4. **控制 attribute 数量**

WebGL attribute 数量有上限。粒子系统里多个 float 参数优先打包：

```text
4 个 float -> vec4
2 个 float -> vec2
局部坐标 -> 复用 position
```

不要为每个参数都单独开一个 attribute。

5. **不要只依赖 `npm run build`**

构建通过不代表 WebGL 运行正确。至少还要做一次浏览器运行检查：

- 打开页面
- 看 console 是否有 shader / WebGL 报错
- 单独显示目标粒子层
- 用 debug shader 强制输出可见点

## 结论

这次真正的问题不是透明度、滚动时机或粒子尺寸，而是 **WebGL attribute 超限导致轮廓 shader 渲染失败**。

正确修复方向是 `App1.jsx` 的做法：减少 attribute 数量、打包参数、复用 `position`，并保持 shader 声明、数据生成、JSX 绑定三者一致。
