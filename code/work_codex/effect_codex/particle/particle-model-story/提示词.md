最重要的一句话是：
禁止直接在模型 A 和模型 B 之间插值；必须先把模型 A 完全转换为独立散点场，保持一段滚动距离，再从同一个散点场逐步汇聚成模型 B。


请在当前项目中实现一个“多 GLB 模型粒子滚动叙事效果”。

不要只给方案，直接检查现有项目、修改代码、运行构建并验证最终效果。只保留当前最终版本，不需要历史演进版本。

一、效果目标

1. 页面上传或配置多个 GLB/GLTF 模型。
2. 所有模型都以 Three.js 粒子形式展示。
3. 页面采用普通连续滚动：
   - 不使用一滚一屏。
   - 不使用 scroll-snap。
   - 不使用强制吸附。
   - 不阻止浏览器默认滚动。
4. 滚动位置实时控制相邻模型之间的粒子变化。
5. 动画必须支持反向滚动，并沿完全相同的轨迹返回。
6. 文案直接写在 index.html 中，不通过 JavaScript 数组生成。
7. GSAP + ScrollTrigger 负责文案时间轴，Three.js Shader 负责粒子变形。

二、模型切换的硬性要求

禁止直接执行：

mix(modelAPosition, modelBPosition, progress)

模型之间必须经过一个独立的空间散点场，使用三阶段状态机：

- progress 0.0～0.4：
  模型 A 逐步打散。
  滚动一点只打散一点。
  到 0.4 时模型 A 的轮廓必须完全消失。

- progress 0.4～0.6：
  粒子保持完全散开的空间状态。
  此时不能看出模型 A 或模型 B 的轮廓。
  可以加入轻微旋流、纵深漂移和呼吸效果。

- progress 0.6～1.0：
  散点逐步汇聚成模型 B。
  滚动一点只汇聚一点。
  到 1.0 时模型 B 才完整呈现。

反向滚动必须依次执行：

模型 B → 散点场 → 模型 A

不能重新随机，不能跳变。

三、Shader 实现要求

顶点 Shader 至少具有三个位置状态：

- fromPosition：旧模型位置。
- scatterPosition：独立空间散点位置。
- toPosition：新模型位置。

参考计算逻辑：

float scatterProgress = smoothstep(
  0.0,
  uScatterEnd,
  uTransition
);

float gatherProgress = smoothstep(
  uGatherStart,
  1.0,
  uTransition
);

vec3 transformed = mix(
  fromPosition,
  scatterPosition,
  scatterProgress
);

transformed = mix(
  transformed,
  toPosition,
  gatherProgress
);

scatterPosition 必须：

1. 使用每颗粒子的固定种子生成。
2. 使用独立哈希生成三个方向分量。
3. 不能每帧调用随机函数。
4. 不能过度依赖原模型位置，否则散开后仍会保留模型轮廓。
5. 相同滚动进度必须得到相同位置。
6. 支持正向和反向滚动。

中段漂移只能乘以散开权重，模型完整时不能继续扭曲：

scatterWeight =
  scatterProgress * (1.0 - gatherProgress)

四、Three.js uniform 更新要求

必须持有实际 ShaderMaterial 引用：

const materialRef = useRef(null)

滚动变化时，必须更新 GPU 当前使用的真实 uniform：

materialRef.current.uniforms.uTransition.value = progress

不能只修改传入 React Three Fiber 的 uniforms 配置对象。

需要确保：

- ScrollTrigger 的 progress 已传给 React。
- React 收到的 progress 已传给 ShaderMaterial。
- ShaderMaterial 的 uTransition 与滚动进度一致。
- 模型索引变化时不会直接替换画面造成跳变。

五、配置要求

在 index.html 中暴露配置：

window.PARTICLE_STORY_CONFIG = {

- 必须满足 scatterEnd < gatherStart。

六、模型兼容要求

需要支持随意替换 GLB/GLTF：

- 遍历模型中的全部 Mesh。
- 应用节点世界变换。
- 支持多 Mesh、嵌套节点、缩放、旋转和位移。
- 尽量兼容 Draco、Meshopt 和 KTX2。
- 对不同尺寸模型进行居中和统一尺寸归一化。
- 不同模型可以配置不同粒子数量、颜色和尺寸。
- 粒子数量不同时，通过透明度控制多余粒子，不在切换时重建 Geometry。

GSAP 只负责：

- 文案退出。
- 文案与当前模型章节的节奏配合。

模型粒子进度必须直接跟随滚动距离，不使用自动补间到目标值。

八、验证标准

实现后必须进行以下验证：

1. progress 约为 0.2：
   - 只能看到模型 A 部分打散。
   - 不能提前出现模型 B。

2. progress 约为 0.5：
   - 模型 A 和模型 B 的轮廓都必须消失。
   - 画面只能看到随机空间粒子场。

3. progress 约为 0.8：
   - 模型 B 只能部分汇聚。
   - 不能提前完整显示。

4. 从 0.8 反向滚动到 0.2：
   - Shader progress 必须同步返回。
   - 粒子沿原路径返回。
   - 不能闪烁、跳变或重新随机。

5. 不要只检查 DOM 中的 progress 数值。
   必须通过浏览器截图实际确认 0.5 时模型轮廓已经消失。
