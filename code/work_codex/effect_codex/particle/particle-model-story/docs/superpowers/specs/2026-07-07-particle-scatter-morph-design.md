# 粒子模型滚动打散过渡设计

## 目标

把当前模型之间的线性粒子变形改为可逆的三阶段滚动过渡：旧模型逐渐打散、粒子保持短暂漂浮、新模型逐渐汇聚。动画进度严格跟随页面滚动，不使用一滚一屏或自动播放。

## 滚动阶段

- `0% ~ 40%`：旧模型从完整轮廓逐渐移动到稳定的空间散点场。
- `40% ~ 60%`：粒子保持完全打散，并加入轻微旋流和深度漂移。
- `60% ~ 100%`：空间散点逐渐汇聚成下一个模型。
- 反向滚动使用同一进度函数，因此轨迹连续、可逆且不会重新随机。

## 技术设计

### 时间轴

`story-timeline.js` 继续计算相邻章节中心点之间的归一化进度，并把原始 `0 ~ 1` 进度发送给 React 粒子层。文案 GSAP 时间轴保持不变。

### 粒子 Shader

顶点 Shader 不再直接从旧模型位置插值到新模型位置，而是计算三个稳定位置：

1. 旧模型采样位置。
2. 基于粒子固定随机方向生成的空间散点位置。
3. 新模型采样位置。

Shader 根据阶段分别执行 `旧模型 → 散点场` 与 `散点场 → 新模型` 插值。中段只叠加连续的轻微旋流，不重新生成随机数。

### 配置

在 `index.html` 的 `window.PARTICLE_STORY_CONFIG` 中暴露：

```js
morphPhases: {
  scatterEnd: 0.4,
  gatherStart: 0.6
}
```

`config.js` 负责校验范围，并保证 `scatterEnd < gatherStart`。现有 `scatterStrength` 和 `curlStrength` 继续控制散布距离与旋流强度。

## 边界与降级

- 第一屏顶部保持第一个完整模型，最后一屏中心之后保持最后一个完整模型。
- 模型粒子数量不同的情况继续通过透明度属性处理，不改变现有最大缓冲区策略。
- `prefers-reduced-motion` 保持现有降级逻辑。
- OrbitControls、鼠标排斥、HTML 文案结构和 CMS 字段结构不改。

## 验收标准

1. 从第一屏滚向第二屏时，前 40% 只看到第一个模型逐步打散。
2. 40% 时第一个模型完全消失为散点，60% 前第二个模型不开始成形。
3. 后 40% 随滚动逐步汇聚，100% 才完整呈现第二个模型。
4. 反向滚动过程连续且完全可逆。
5. 三组模型切换使用同一逻辑，构建无错误，浏览器控制台无运行时错误。
